OpenFOAM v2512

caseProperties

正在打开最新内容…

createZeroDirectory 使用的算例描述文件，指定初始值、边界类别、模板选项与区域。

简要介绍

caseProperties 以较集中的方式描述算例的初值、边界类别和区域，供 createZeroDirectory 结合模板生成场文件。它适合自动准备 0 目录，减少对每个字段分别重复填写相似边界信息。

位置：system/caseProperties

参数说明

条目含义
initialConditions生成初始场时使用的变量和值，常写作 p uniform 100000 或 U uniform (0 0 0)。
rho密度或密度场引用；是否为量纲标量、常量或场名由模型定义。
T温度值或温度场引用，通常采用热力学温度 K。
boundaryConditions以逻辑边界组组织模板；每组再通过 patches 对应实际网格边界。
category边界模板类别，例如 wall 或 inlet，影响可选择的模板类型。
type运行时选择的模型或操作类型，同一个关键字在不同子字典中具有不同注册表。
patches参与该操作的边界列表，必须对应网格中的实际 patch 名称。
options热传递、流动等边界模板选项；由所用模板库定义。
values传给模板的字段或数值，示例通过 $/initialConditions 引用根字典中的默认值。
omega角速度参数或湍流比耗散率场名，二者物理意义与量纲不同。

模型选择与嵌套参数

参数说明
flowSpecification按流动规格组织初始场和边界模板；与所选求解器、不可压缩/可压缩形式一致。
wallFunction是否按模板采用壁面函数；必须同时检查湍流模型、近壁网格及 y+。
nut / k / epsilon / omega由模板生成的湍流字段。修改规格后需重新生成相应 0/ 文件，直接改 caseProperties 不会自动改写已有初值。
motorbike 等区域名称边界或几何分组名，与模板和网格中的名称对应。

配置示例

配套案例文件

下载配置后，可从案例目录取得配套网格、初始场和 include 文件。

案例文件 1 · preProcessing/createZeroDirectory/snappyMultiRegionHeater

算例问题：snappyMultiRegionHeater

本例为后续流动或传热计算建立初始场文件。用表面几何生成流体与固体分区网格，再计算加热器与周围流体之间的共轭传热。网格区域名称需要与物性、初始场和温度接口一致；算例用于检查自动分区、区域连接和热量传递。 此目录侧重根据算例属性生成 0/ 下的场和边界配置，完整求解还需使用相应的流动或传热算例。

算例出处：OpenCFD OpenFOAM v2512 官方教程 preProcessing/createZeroDirectory/snappyMultiRegionHeater。

createZeroDirectory 使用 caseProperties 中的物理角色生成初始场。这里配置多区域加热器的 leftSolid 固体区域。

  • initialConditions 设 p=100000 Pa、rho=8000 kg/m³、T=300 K，供后面的边界模板引用。
  • thermalWalls 覆盖 minX、minZ、maxZ，heatTransfer adiabatic 指定绝热处理。
  • thermalCoupledWalls 用 ".*_to_.*" 匹配区域间界面，heatTransfer thermalCoupled 生成热耦合设置。
  • values $/initialConditions 从顶层初始条件引用参数，避免在各边界重复维护数值。

给固体换材料时修改密度及相应热物性；生成后检查界面两侧的边界名称与温度耦合关系。

下载配置 · 源码 · 案例目录

配置出处：OpenCFD OpenFOAM v2512 官方教程 preProcessing/createZeroDirectory/snappyMultiRegionHeater/system/leftSolid/caseProperties（原文件）。

/*--------------------------------*- C++ -*----------------------------------*\
| =========                 |                                                 |
| \\      /  F ield         | OpenFOAM: The Open Source CFD Toolbox           |
|  \\    /   O peration     | Version:  v2512                                 |
|   \\  /    A nd           | Website:  www.openfoam.com                      |
|    \\/     M anipulation  |                                                 |
\*---------------------------------------------------------------------------*/
FoamFile
{
    version     2.0;
    format      ascii;
    class       dictionary;
    object      caseProperties;
}
// * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * //

initialConditions
{
    p       uniform 100000;
    rho     uniform 8000;
    T       uniform 300;
}


boundaryConditions
{
    thermalWalls
    {
        category    wall;
        type        thermal;
        patches     (minX minZ maxZ);
        options
        {
            heatTransfer adiabatic;
        }
        values
        {
            $/initialConditions;
        }
    }
    thermalCoupledWalls
    {
        category    wall;
        type        thermal;
        patches     (".*_to_.*");
        options
        {
            heatTransfer thermalCoupled;
        }
        values
        {
            $/initialConditions;
        }
    }
}

案例文件 2 · preProcessing/createZeroDirectory/cavity

算例问题：cavity

本例为后续流动或传热计算建立初始场文件。封闭方腔的顶盖沿切向运动，其他壁面保持静止，顶盖通过黏性作用带动腔内流体。计算产生主涡和角部回流，用于检查速度、压力以及网格分辨率对流动结构的影响。 此目录侧重根据算例属性生成 0/ 下的场和边界配置，完整求解还需使用相应的流动或传热算例。

算例出处：OpenCFD OpenFOAM v2512 官方教程 preProcessing/createZeroDirectory/cavity。

方腔的 caseProperties 将“运动顶壁、静止固壁”等物理角色转换为具体的 U、p 边界配置。

  • 初始 U (0 0 0) 表示静止流体，p 0 给出压力初值。
  • topWall 对应 movingWall，motion moving 和 U (1 0 0) 让顶壁沿 x 方向以 1 m/s 运动。
  • walls 对应 fixedWalls，motion stationary 生成静止无滑移壁面条件。
  • 两组壁面都采用 type noSlip；运动壁面的无滑移速度等于壁面自身速度。模板中其他通用选项由生成器按所选模型处理。

改变顶盖速度时修改 topWall 的 U，再重新生成初始场；可用生成后的 0/U 检查方向与数值。

下载配置 · 源码 · 案例目录

配置出处：OpenCFD OpenFOAM v2512 官方教程 preProcessing/createZeroDirectory/cavity/system/caseProperties（原文件）。

/*--------------------------------*- C++ -*----------------------------------*\
| =========                 |                                                 |
| \\      /  F ield         | OpenFOAM: The Open Source CFD Toolbox           |
|  \\    /   O peration     | Version:  v2512                                 |
|   \\  /    A nd           | Website:  www.openfoam.com                      |
|    \\/     M anipulation  |                                                 |
\*---------------------------------------------------------------------------*/
FoamFile
{
    version     2.0;
    format      ascii;
    class       dictionary;
    object      caseProperties;
}
// * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * * //

initialConditions
{
    U           uniform (0 0 0);
    p           uniform 0;
}

boundaryConditions
{
    topWall
    {
        category        wall;
        patches         (movingWall);
        type            noSlip;
        options
        {
            wallFunction    highReynolds;
            motion          moving;
        };
        values
        {
            U           uniform (1 0 0);
        }
    }

    walls
    {
        category        wall;
        patches         (fixedWalls);
        type            noSlip;
        options
        {
            wallFunction    highReynolds;
            motion          stationary;
        };
    }
}

案例文件 3 · preProcessing/createZeroDirectory/motorBike

算例问题：motorBike

本例为后续流动或传热计算建立初始场文件。来流绕过摩托车与骑手组合外形，表面附近形成边界层，后方形成分离尾流。主要结果为压力、速度、阻力及尾流结构；包含伴随设置时，还用于评价表面形状对目标函数的影响。 此目录侧重根据算例属性生成 0/ 下的场和边界配置，完整求解还需使用相应的流动或传热算例。

算例出处：OpenCFD OpenFOAM v2512 官方教程 preProcessing/createZeroDirectory/motorBike。

motorBike 的 caseProperties 用于创建外流计算的初始场和边界条件。它把车体、地面、入口、出口分别描述为物理边界。

  • 初始 U (20 0 0) 设来流速度 20 m/s，k 0.24、omega 1.78 给出湍流初值。
  • motorBikeGroup 采用静止无滑移壁面和 highReynolds 壁面处理；地面 lowerWall 同样为无滑移壁面。
  • inlet 的 subSonic、fixedVelocity 使用给定入口速度，outlet 的 returnFlow default 为可能的回流提供模板处理。
  • upperWall 和 frontAndBack 使用 slip，减少外围边界对切向速度的约束。

改变来流工况时同时检查湍流入口值和车体首层网格；若模拟移动地面，应更新地面运动选项及速度。

    k           uniform 0.24;

        type            noSlip;

        }
