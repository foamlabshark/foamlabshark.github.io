第七章 硬件实现（Hardware Implementation）

NVIDIA GPU 架构围绕一组可扩展的、多线程流式多处理器（Streaming Multiprocessor，SM）构建。当主机 CPU 上的 CUDA 程序启动一个内核网格时，网格中的线程块会被枚举，并分配给具有可用执行资源的多处理器。一个线程块中的线程会在同一个多处理器上并发执行，同一个多处理器也可以并发执行多个线程块。当线程块结束时，新的线程块会被调度到空出的多处理器资源上。

多处理器的设计目标是并发执行数百个线程。为了管理如此大量的线程，它采用一种称为 **SIMT（Single-Instruction, Multiple-Thread，单指令多线程）**的独特架构，详见“SIMT 架构”一节。指令通过流水线执行：既利用单个线程内部的指令级并行性，也通过硬件多线程充分利用线程级并行性。与 CPU 核心不同，GPU 的指令按顺序发出，不使用分支预测或推测执行。

“SIMT 架构”和“硬件多线程”介绍所有设备共有的流式多处理器架构特征。“计算能力 5.x”“计算能力 6.x”和“计算能力 7.x”则分别介绍计算能力为 5.x、6.x 和 7.x 的设备细节。

NVIDIA GPU 架构使用**小端序（little-endian）**表示方式。

7.1 SIMT 架构（SIMT Architecture）

多处理器会以每组 32 个并行线程的方式创建、管理、调度和执行线程，这种线程组称为 warp。

构成一个 warp 的各线程会从相同的程序地址开始执行，但每个线程都有自己的指令地址计数器和寄存器状态，因此可以自由分支并独立执行。warp 一词源自编织技术，指最早的并行线程技术。**半 warp（half-warp）**是一个 warp 的前半部分或后半部分；**四分之一 warp（quarter-warp）**则是一个 warp 的四个等分之一。

当多处理器获得一个或多个线程块执行任务时，会将它们划分为多个 warp，并由 warp 调度器调度执行。线程块划分为 warp 的方式始终相同：每个 warp 包含线程 ID 连续递增的线程，第一个 warp 包含线程 0。“线程层次结构”一节说明了线程 ID 与线程块中线程索引之间的关系。

一个 warp 同一时刻执行一条共同指令。因此，当一个 warp 中的 32 个线程都沿相同执行路径运行时，效率最高。如果线程因数据相关的条件分支而发生分支发散（branch divergence），warp 就会依次执行各条被选中的分支路径，并禁用当前不在该路径上的线程。分支发散只会发生在同一个 warp 内；不同 warp 彼此独立，无论它们执行相同还是不同的代码路径。

SIMT 架构与 SIMD（Single Instruction, Multiple Data，单指令多数据）向量组织方式相似：一条指令控制多个处理单元。关键区别在于，SIMD 向量组织会向软件显式暴露 SIMD 宽度，而 SIMT 指令规定的是单个线程的执行与分支行为。与 SIMD 向量机不同，SIMT 允许程序员为相互独立的标量线程编写线程级并行代码，也允许为协同线程编写数据并行代码。

从正确性角度而言，程序员基本可以忽略 SIMT 的具体行为；不过，如果能让一个 warp 中的线程尽量少发生分支发散，通常可以显著提升性能。这类似于传统程序设计中的缓存行：设计正确性时可以忽略缓存行大小，但若要达到峰值性能，就必须在代码结构中考虑它。另一方面，向量架构要求软件主动将加载操作合并为向量，并手动管理分支发散。

在 NVIDIA Volta 架构之前，一个 warp 的 32 个线程共用同一个程序计数器，并通过活动掩码指定当前处于活动状态的线程。因此，在发散区域或处于不同执行状态的同一 warp 线程，不能相互发信号或交换数据。若算法需要在线程之间进行由锁或互斥量保护的细粒度数据共享，就可能因竞争线程所属 warp 的不同而导致死锁。

从 NVIDIA Volta 架构开始，**独立线程调度（Independent Thread Scheduling）**允许线程之间实现更充分的并发，不再受 warp 同步方式的旧限制。GPU 会为每个线程维护执行状态，包括程序计数器和调用栈，并能以单线程粒度让出执行，以更好地利用执行资源，或允许一个线程等待另一个线程产生数据。调度优化器会决定如何将同一 warp 中的活动线程组合成 SIMT 执行单元。这在保留以往 NVIDIA GPU 高吞吐量的同时，提供了更大的灵活性：线程可以在小于一个 warp 的粒度上发散和重新汇合。

独立线程调度可能导致实际参与执行代码的线程集合与开发者预期不同，特别是当代码假设旧架构中同一 warp 的线程会始终同步执行时。任何 warp 同步代码（例如无需显式同步的 warp 内归约）都应重新检查，以确保与 NVIDIA Volta 及后续架构兼容。更多细节见“计算能力 7.x”。

注意： 参与当前指令执行的 warp 线程称为活动线程；没有执行当前指令的线程称为非活动（禁用）线程。线程可能因多种原因处于非活动状态，例如它比同一 warp 的其他线程更早退出、执行了不同的分支路径，或所属线程块的线程总数不是 warp 大小的整数倍而成为最后一组中的剩余线程。

如果 warp 中多个线程通过非原子指令向全局内存或共享内存的同一位置写入，发生的串行写入次数会随设备计算能力而变化，最终由哪个线程完成写入则未定义。如果 warp 中多个线程通过原子指令对全局内存的同一位置执行读取、修改和写入，那么每次原子操作都会发生并按顺序串行化，但操作顺序未定义。

注：**warp 同步（warp-synchronous）**指代码隐式假定同一 warp 中的线程在每条指令处都已同步。

7.2 硬件多线程（Hardware Multithreading）

多处理器处理的每个 warp，其执行上下文（程序计数器、寄存器等）在 warp 的整个生命周期内都保存在芯片上。因此，从一个执行上下文切换到另一个上下文不产生切换成本。在每次发出指令时，warp 调度器都会选择一个具有就绪线程、能够执行下一条指令的 warp，并向该 warp 的活动线程发出指令。

每个多处理器都有一组 32 位寄存器，这些寄存器会分配给各个 warp；同时还具有并行数据缓存或共享内存，并按线程块进行分配。

对于某个内核，多处理器能够同时驻留并处理的线程块和 warp 数量，取决于该内核使用的寄存器和共享内存数量，以及多处理器可用的寄存器和共享内存容量。此外，每个多处理器可驻留的线程块数量和 warp 数量也有上限。这些上限，以及多处理器可用的寄存器和共享内存容量，都取决于设备的计算能力，具体见“计算能力”。如果多处理器可用的寄存器或共享内存不足以处理至少一个线程块，内核启动就会失败。

一个线程块中的 warp 总数为：

\[ N_{\text{warps}}=\left\lceil\frac{T}{W_{\text{size}}}\right\rceil \]

其中：

  • \(T\) 是每个线程块中的线程数；
  • \(W_{\text{size}}\) 是 warp 大小，等于 32；
  • \(\lceil x/y\rceil\) 表示将 \(x/y\) 向上取整。

每个线程块所分配的寄存器总量和共享内存总量，可通过 CUDA Toolkit 提供的 CUDA Occupancy Calculator 进行分析。
